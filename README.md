# Link Check

Independent MIT mini-app for App Composer #50. Inspect raw public HTML, Open Graph and X image responses, actual file dimensions and SEO metadata. Export version 1 `page-inspection` reports for the Composer review surface. No login, database, model calls, private credentials or arbitrary build service.

Reviewed 13 October 2026. Source: https://github.com/loftwah/app-composer-linkcheck. Launch target: https://share.loftwah.com. Independent Cloudflare Worker with TypeScript, Effect 4.0.4 and native browser UI. App Composer's EmDash owns its catalogue, not this app's runtime. Fonts: Space Grotesk by Florian Karsten, SIL OFL; licence retained.

`pnpm install`, `pnpm dev`, `pnpm check`, `pnpm test:metadata`, `pnpm test:fetch`. Tests take under a second locally and use fictional fixtures without network writes. `pnpm build` produces a real Wrangler bundle. `pnpm deploy` requires clean reviewed pushed main, checks/builds and verifies the exact live commit. No GitHub Actions.

Fork configuration: change the exact public host list in `src/inspection.ts`, deployment target/account in `wrangler.jsonc`, public canonical/social URLs in `public/index.html`, the content-security image origins and source URLs. Review hosts before permitting fetches. Unknown hosts, IPs, non-HTTPS, credentials, query strings, private/API paths and encoded paths are denied. Every redirect and image URL is revalidated. No cookies or auth headers are forwarded. HTML is capped at 512 KiB, each image at 5 MiB; three redirects and a 12-second whole-inspection timeout. Scripts are never executed. Reports contain extracted metadata rather than full HTML. They are untrusted data, not agent instructions or authority.

Platform layouts are approximate. Open Graph protocol, LinkedIn, Slack and Google title guidance were reviewed using official documentation. X's old large-card page redirected to its general API overview; Facebook best practices returned 429. Their current limits are marked unverified. Discord/WhatsApp/iMessage native acceptance remains unverified. No indexing, ranking, actual platform unfurl, robots.txt access or rich-result eligibility claim follows from this report. Dates are explicit; guidance is not silently refreshed by the clock. Recheck relevant official guidance when a rule changes, preserve the source and label unavailable results.

MP requested current AI failure-mode awareness: untrusted web metadata may contain prompt injection, tool instructions are not owner authority, stale APIs need verification, and a good-looking report is not production proof. Typed errors preserve failed inspections; cancelled/partial work cannot create evidence of a successful platform check. This app uses deterministic parsing and never submits fetched text to a model. See https://openai.com/index/designing-agents-to-resist-prompt-injection/ (11 March 2026).

The public inspection route is capped at 20 requests per minute per Cloudflare location across callers, using the native Workers rate-limit binding. It fails closed if that binding is absent. This is an abuse limit, not a global or dollar spending cap. No D1/R2/paid SEO resource or new subscription is required. Official binding behavior: https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/ (reviewed 13 October 2026).

The inspection API accepts bounded JSON POST bodies, keeping pasted target URLs out of request query logs. Request bodies and reports are not application-persisted; standard Cloudflare operational request logs still apply.

Site identity checks inspect the first declared favicon and Apple touch icon (256 KiB each), optional manifest JSON (64 KiB), and theme colour. SVG is parsed as inert text and never previewed or executed; viewBox coordinates are labelled separately from raster pixels. Nested manifest icons, installation and browser selection among icon variants remain unverified. Guidance reviewed 13 October 2026: https://html.spec.whatwg.org/multipage/links.html#rel-icon and https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/link. Run `pnpm test:identity` for this focused group.

Contributions: [Contributing](CONTRIBUTING.md), [Code of Conduct](CODE_OF_CONDUCT.md), [Security](SECURITY.md), [Accessibility](ACCESSIBILITY.md). The first viewport presents the inspection task; results lead with site identity and share preview, with passed checks and guidance collapsed. Original generated Composer artwork is self-hosted; its prompt is retained in `public/composer-art.prompt.txt`.

Cloudflare injects existing analytics and JavaScript detections at the edge. HTML responses use fresh 128-bit CSP nonces and no shared caching; the CSP permits only the official analytics script path and same-origin collection. It does not allow arbitrary inline scripts. See https://developers.cloudflare.com/cloudflare-challenges/challenge-types/javascript-detections/ and https://developers.cloudflare.com/web-analytics/faq/ (reviewed 13 October 2026).

Diagnostics release, reviewed 14 October 2026: findings now carry an area, priority, explanation, context-sensitive next step and official source. Ordered OG image properties are compared with actual primary-file dimensions/type. The HTML outline, missing versus decorative alt attributes, canonical/share identity, restricted zoom, title/description character counts and JSON-LD arrays/@graph are visible without an invented SEO score or universal character cutoff. Optional discovery reads robots.txt (64 KiB) and one declared/default sitemap (256 KiB) through the same redirect/host/time boundary. Directives are evidence, not a simulated crawler verdict; child maps/listed URLs are never fetched and XML/schema/indexing remain unverified. No auxiliary discovery requests occur by default.

## Health and optional usage

Reviewed 14 October 2026. `GET /healthz` (or the declared mount plus `/healthz`) returns public liveness and exact source revision. It does not query storage, inspect credentials or prove a full user journey. `HEAD` is supported; other methods return 405.

Optional server-only daily counts use `USAGE_ENDPOINT` (an explicit HTTPS app-scoped endpoint) and `USAGE_TOKEN` (a write-only runtime secret). Both are absent by default, so forks remain independent. The copied MIT publisher derives from App Composer `lib/usage/publisher.mjs`; it is owned and deployable here, without a Composer package or Woodhouse runtime dependency. Failure or a 1.5-second timeout drops a count without blocking the app; there are no retries. Only successful public home-page opens, completed inspections are published. No visitor, URL, referrer, entered text, identity, profile, filename or passphrase is sent. `X-Composer-Verification: 1` excludes synthetic release probes.

The launch operator enables its own instances through Wrangler secrets; do not copy those secrets into a fork. The public [app activity](https://composer.loftwah.com/activity) explains retention, limits and missing-count/bot caveats.

Add `?vitals=1` to the public page, then open “Page performance” for local LCP/INP/CLS measurements. Values apply to this load only; unsupported metrics say unavailable. The self-hosted standard `web-vitals` 6.2.3 bundle and Apache licence/provenance are retained. No values, element attribution or page data are uploaded or persisted. Developer console links stay public and do not print app contents.
